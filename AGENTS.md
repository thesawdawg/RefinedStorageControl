# RefinedStorageControl

7 Days to Die mod: a wired storage network for centralized access to connected
containers and powered digital disks, with manual terminal crafting via native
stations. Targets game 3.3.0; managed assembly references come from
`<GameRoot>\7DaysToDie_Data\Managed` via the `GameManaged` msbuild property.

## Start here

1. [DEVELOPMENT.md](DEVELOPMENT.md): current status and next work, new-machine
   setup, build/test/install, the art pipeline, and gotchas already found.
2. `TODO.md` (milestones, what is built and awaiting in-game checks),
   `SPECS.md` (requirements with IDs, acceptance scenarios, open decisions),
   `RefinedStorage-Design.md` (decision record and per-phase implementation
   notes; the source of truth).
3. The owner tests in game from the `P*-TEST-GUIDE.md` files and reports back;
   fix what they find, rebuild with `-Install`, and say what to re-check.

## Layout

- `Source/` — the mod assembly (`RefinedStorageControl.dll`, net48).
  - `Source/Core/` — network topology registry (pure).
  - `Source/Storage/` — disk records, the world disk store (cabinet slots,
    world binding) and binary serialization (pure).
  - `Source/Access/` — owner + allowlist ACLs (pure).
  - `Source/Routing/` — transfer budget, stack placement, provider ordering
    and filters (pure).
  - `Source/View/` — terminal search, categories, sorting and favorites
    ordering (pure).
  - `Source/Crafting/` — ingredient planning, station choice, countdown
    reservations, job records and their file format (pure).
  - `Source/Config/` — `RscSettings`: Settings.xml values, ranges, defaults (pure).
  - `Source/Diagnostics/` — the bounded journal buffer (pure).
  - `Source/Game/` — the only layer allowed to touch game/Unity types
    (`IModApi` entry point, `Log`, console commands).
    - `Source/Game/Topology/` — wire tree projection and wire rules.
    - `Source/Game/Providers/` — vanilla container providers, the host
      transfer service, and `rsc net` commands.
    - `Source/Game/Persistence/` — RSC save files (`nodes.dat`, `disks.dat`,
      `jobs.dat` via `RscSaveFile`) and the save/removal hooks.
    - `Source/Game/Blocks/` — `BlockRscNode` (E action for terminals,
      interfaces and drive cabinets; pickup/destruction hooks; sets the
      `T_Block` tag on bundled models; keeps the vanilla powered tile entity).
    - `Source/Game/UI/` — XUi controllers and host/client window backends;
      layouts live in `Mod/Config/XUi_InGame/`.
    - `Source/Game/Crafting/` — native station adapter, the host crafting
      service (countdown, dispatch, collection, XP, claim keepalive) and
      `rsc craft` commands.
    - `Source/Game/Net/` — co-op network packages and the client session.
      Write primitives through `(BinaryWriter)_bw`: the game's
      PooledBinaryWriter has span overloads net48 cannot resolve.
    - `Source/Game/Prototypes/` — P0 `rsc proto` commands (dev only).
- `Tests/` — net48 console harness compiling `Source/**` **except** `Source/Game/`.
  This is the purity check: Core/Storage/Access/Routing must never use game or
  Unity types. If the test build needs a game reference, the purity boundary
  has been violated.
- `Mod/` — deployable mod files (`ModInfo.xml`, `Settings.xml`, `README.txt`,
  `Config/`, `UIAtlases/ItemIconAtlas/` icons, `Resources/rsc.unity3d` models).
- `Art/` — Blender scene, 512 px previews and FBX meshes for the RSC models;
  all generated by `Tools/Art/rsc_art.py`, which also writes the shipped
  160 px icons to `Mod/UIAtlases/ItemIconAtlas/`. Re-run after changing it:
  `blender -b --factory-startup -P Tools/Art/rsc_art.py -- <repo root>`.
- `Tools/Unity/` — `RscBundle` (Unity 2022.3.62 project; only `Assets/Editor`,
  `Packages`, `ProjectSettings` are source) and `BuildBundle.ps1`, which
  re-exports the Blender models and builds `Mod/Resources/rsc.unity3d` in
  batch mode. The bundle is committed, so `Tools/Build.ps1` does not need
  Unity; re-run `pwsh ./Tools/Unity/BuildBundle.ps1` after changing models.
  The Unity version must match the game's (3.3 b18: 2022.3.62).
- `Release/` — release drafts (Nexus page); never packaged or published by the build.
- `Artifacts/RefinedStorageControl/` — packaged mod produced by the build
  (gitignored).

## Build and test

```
pwsh ./Tools/Build.ps1
```

Builds both projects, runs the test harness, and assembles the packaged mod.
The build fails if the artifact contains any file that also exists in the
game's Managed directory (no game assemblies may ship).

```
pwsh ./Tools/Build.ps1 -Install
```

Additionally mirrors the artifact into `Mods/RefinedStorageControl_Dev` under
the game root so the mod can be loaded in-game without touching this dev
tree. Close the game first — `RefinedStorageControl.dll` stays locked while
it is running.

## Important

- **Never** place a `ModInfo.xml` at the repo root — this repo sits inside the
  game's Mods folder and the game would load the dev tree. The mod manifest
  lives only in `Mod/`.
- Do not commit build output (`bin/`, `obj/`, `Artifacts/`).
- Decisions still open in `SPECS.md` (F08/F09, and the F12 cap value) must not
  be hardcoded as accepted — keep them configurable or unimplemented. When the
  owner accepts a decision, record it in the design doc and SPECS together.
- Pushing, PRs, and publishing (Nexus) need the owner's go-ahead.
